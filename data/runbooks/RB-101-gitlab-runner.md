# Задачи CI висят в pending — проблема с раннерами

## Общие раннеры
| Раннер | Теги | Назначение |
|---|---|---|
| `docker-runner-01..03` | `docker`, `linux` | Сборка и тесты в контейнерах, `concurrent = 10` на раннер |
| `k8s-runner` | `k8s`, `deploy` | Деплой в кластеры, только для защищённых веток |
| `win-runner-01` | `windows`, `dotnet-framework` | Сборки под .NET Framework, `concurrent = 2` |

## Диагностика
1. Проверить теги задачи — задача берётся раннером только при совпадении **всех** тегов.
2. Admin → CI/CD → Runners: раннер онлайн, когда последний контакт.
3. На хосте раннера:
   ```bash
   sudo gitlab-runner status
   sudo gitlab-runner verify
   journalctl -u gitlab-runner --since "1 hour ago"
   ```
4. Все слоты заняты — очередь нормальна в часы пик (11:00–13:00 и 16:00–18:00).

## Решение
- Раннер офлайн — `sudo systemctl restart gitlab-runner`, при повторении — проверить диск и память хоста.
- Деплой-задача в pending на незащищённой ветке — это ожидаемо: `k8s-runner` берёт задачи только с защищённых веток.
- Командам с постоянной нагрузкой выделяется собственный раннер по заявке в DevOps.
