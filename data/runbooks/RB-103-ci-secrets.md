# Секреты в CI/CD и их утечка

## Где хранить секреты
- Основное хранилище секретов — **HashiCorp Vault** (`vault.corp.local`). Приложения в Kubernetes получают секреты через Vault Agent / External Secrets.
- В GitLab CI секреты задаются переменными с флагами **Masked** и **Protected** (доступны только в защищённых ветках).
- Хранить секреты в репозитории, в `.gitlab-ci.yml`, в образах и в README запрещено.

## Проверка
На всех проектах включён secret detection в пайплайне. Найденный секрет блокирует merge request.

## Если секрет утёк
(закоммичен в репозиторий, выведен в лог, отправлен в чат)
1. **Немедленно отозвать или сменить секрет** (ротация) — удаление коммита не помогает: история и форки остаются.
2. Сообщить в Security (доб. 5555 или security@corp.local) в течение **1 часа** с момента обнаружения.
3. Проверить журналы использования секрета за период утечки.
4. После ротации — удалить секрет из истории (`git filter-repo`) по согласованию с Security.

## Срок жизни
Статические секреты сервисов ротируются не реже раза в **180 дней**. Где возможно, использовать динамические секреты Vault (БД) со сроком жизни до 24 часов.
