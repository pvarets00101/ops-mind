# Отставание репликации PostgreSQL

## Архитектура
- Продуктивные кластеры работают под управлением **Patroni**: 1 лидер и 2 синхронизируемые реплики, хранилище конфигурации — etcd.
- Приложения пишут через адрес лидера (`<cluster>-rw.corp.local`), читают отчёты через реплики (`<cluster>-ro.corp.local`).

## Порог алерта
Отставание реплики больше **60 секунд** — warning, больше 300 секунд — critical (реплика исключается из балансировки чтения).

## Диагностика
```bash
patronictl -c /etc/patroni/patroni.yml list
```
```sql
-- на лидере
SELECT client_addr, state, write_lag, flush_lag, replay_lag FROM pg_stat_replication;
```

## Типовые причины
- Долгий аналитический запрос на реплике конфликтует с применением WAL (`hot_standby_feedback`) — найти и завершить запрос.
- Массовая загрузка данных на лидере — дождаться окончания, если отставание уменьшается.
- Сеть или диск реплики — проверить метрики хоста.

## Переключение лидера
Ручное переключение (`patronictl switchover`) выполняется только командой Database и только в окно изменений, кроме аварийных случаев.
