# Высокая загрузка процессора на сервере

## Порог алерта
Алерт срабатывает, если загрузка CPU выше **90% в течение 15 минут**.

## Диагностика (Linux)
```bash
top -o %CPU            # какие процессы
pidstat -u 5 3         # динамика по процессам
perf top -p <pid>      # горячие функции процесса
```
Проверить steal time (`%st` в top): значение выше 10% — перегружен хост виртуализации, а не ВМ, передать в Infra (виртуализация).

## Диагностика (Windows)
Process Explorer или `Get-Process | Sort CPU -Desc | Select -First 10`.

## Типовые причины
- Резкий рост нагрузки (сезонность, рассылка, маркетинговая акция) — проверить метрики запросов приложения.
- Бесконечный цикл или утечка после релиза — сравнить с временем деплоя, рассмотреть откат (RB-102).
- Антивирусная проверка или резервное копирование в рабочее время.
- Майнер или вредоносный процесс — незнакомый процесс с высокой нагрузкой: **не завершать**, изолировать и сообщить в Security (RB-111).

## Решение
Добавление vCPU для ВМ требует её перезагрузки: для продуктивных серверов — только в окно изменений (RB-102).
