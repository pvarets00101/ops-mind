# Pod в состоянии CrashLoopBackOff

## Что это значит
Контейнер запускается и падает, Kubernetes перезапускает его с растущей задержкой (до 5 минут).

## Диагностика
```bash
kubectl get pods -n <ns>
kubectl describe pod <pod> -n <ns>        # причина последнего завершения, события
kubectl logs <pod> -n <ns> --previous     # логи упавшего экземпляра
```

## Причины по коду завершения
| Признак | Причина | Решение |
|---|---|---|
| `Reason: OOMKilled`, exit code 137 | Превышен `resources.limits.memory` | Увеличить лимит или найти утечку памяти |
| Exit code 1, ошибка в логах | Ошибка приложения: нет переменной окружения, недоступна БД | Проверить ConfigMap/Secret и зависимости |
| Падает через ~30 с после старта | Не проходит `livenessProbe` | Увеличить `initialDelaySeconds` или исправить health-endpoint |
| Exit code 127 / `exec format error` | Неверная команда или образ под другую архитектуру | Проверить `command` и сборку образа |

## Важно
- Не удалять под в надежде, что «пересоздастся и заработает» — без исправления причины он упадёт снова.
- Если падение началось сразу после деплоя — откатить релиз (`helm rollback`, RB-102), а затем разбираться.
